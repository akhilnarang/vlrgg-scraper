# Google, protocol, crypto, and parser dependency audit

## Result

Keep all 21 changed packages in this slice, subject to the normal full test run before deployment. Three upgrades are especially valuable security fixes: `cryptography`, `hiredis`, and `pyasn1`. The main compatibility risks are the major `protobuf` upgrade and stricter HTTP/2 behavior in `h2`; neither is used directly by application code.

The working lock records a cutoff of `2026-08-25T07:55:48.804499828Z`, corresponding to lock generation at `2026-08-28T07:55:48.804499828Z`. The table uses the earliest distribution upload in PyPI's first-party release JSON as the release-age timestamp. Every selected release predates the cutoff, so every one was at least 72 hours old when the lock was generated.

`msgpack` was also checked and is unchanged at `1.2.1`.

## Artifact-age caveat

`google-auth 2.57.0`, `google-cloud-core 2.7.0`, and `google-cloud-firestore 2.29.0` each first published a universal wheel around `2026-08-24T21:55Z`, about 82 hours before lock generation, so the releases satisfy the stated 72-hour release-age rule. Their source archives were added later:

- [`google-auth` sdist: `2026-08-25T19:18:26.419892Z`](https://pypi.org/pypi/google-auth/2.57.0/json)
- [`google-cloud-core` sdist: `2026-08-25T19:18:43.076706Z`](https://pypi.org/pypi/google-cloud-core/2.7.0/json)
- [`google-cloud-firestore` sdist: `2026-08-25T19:18:51.747442Z`](https://pypi.org/pypi/google-cloud-firestore/2.29.0/json)

Those sdists were younger than 72 hours at lock generation. The deploy target can install the mature universal wheels, so this does not violate a release-age policy. If the intended policy is instead that **every artifact** must age for 72 hours, these three versions should be rolled back to `google-auth 2.56.3`, `google-cloud-core 2.6.1`, and `google-cloud-firestore 2.28.1`; the current release-level age configuration does not express that stricter rule.

## Deployment risk summary

- No rollback is recommended from this audit.
- Preserve the 72-hour cutoff in the dependency tooling; every selected release in this slice passed it.
- Give the full test suite extra weight for `protobuf`, `h2`, and `soupsieve`, because they contain observable API or parsing changes.
- Do not replace `cryptography 50.0.0` with the newer `50.0.1` in this lock: `50.0.1` was first uploaded at [`2026-08-25T19:44:03.155112Z`](https://pypi.org/pypi/cryptography/50.0.1/json), after this lock's cutoff.
